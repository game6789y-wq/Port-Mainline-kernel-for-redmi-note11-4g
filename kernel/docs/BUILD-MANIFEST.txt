Stage 109 DSI/panel/first-kickoff audit:

Stage 110 shutdown / ESD / DSI error audit:
- K7 OFF command table is sent in atomic_disable; panel reset and GPIO9 are powered down in atomic_post_disable; DSI host post-disable follows panel due pre_enable_prev_first ordering.
- No K7 DCS 0x0A status/ESD worker exists (vendor expected value 0x9D). Host RX support exists but K7 does not use it; response parser may return zero for ACK/error or invalid packets, so caller must verify exact response.
- DSI error IRQ collects PLL/FIFO/ACK/timeout/status/lane errors; worker only resets on MDP FIFO underflow and logs/re-enables IRQ for other classes. No automatic PLL/lane or panel ESD recovery.
- Future ESD worker must be serialized/cancellable, read exactly one byte 0x9D, stop before panel OFF, and avoid blind reset. No source/DTS changes or rebuild; display graph remains disabled.

Stage 111 K7 ESD read/lifecycle audit:
- Generic DCS read returns host byte count; MSM one-byte short response copies byte 1 and returns exactly 1. ACK/error and invalid response packet types return 0; failed/short read must not be interpreted as healthy status.
- K7 expected DCS 0x0A value is 0x9D. Future monitor must require `ret == 1 && status == 0x9D`; classify all other outcomes as failed/mismatch.
- Host command transfer uses cmd_mutex, but power-off uses dev_mutex and does not take cmd_mutex; power_on check precedes cmd_mutex. Asynchronous monitor must be synchronously cancelled/drained by DRM lifecycle before host shutdown.
- Never call cancel_delayed_work_sync while holding K7 ctx->lock; cancel outside lock, then lock and OFF/power-down. Add a stopping state to prevent worker re-arm. Observation-only first; no blind reset/recovery.
- Stage 111 is source-level design audit only. No source/DTS changes, no rebuild, no hardware validation; MDSS/DSI0/PHY remain disabled.

Stage 112 DRM/ESD lifecycle audit:
- Bridge chain order is DSI manager -> K7. K7 `pre_enable_prev_first` makes host pre-enable precede panel pre-enable and makes K7 post-disable precede host shutdown. DRM bridge atomic_disable runs before encoder disable; atomic_post_disable runs after encoder disable.
- Proposed ESD delayed work: initialize at probe; arm only after successful panel ON/PPS/refresh enable. In K7 atomic_disable set stopping under ctx->lock, unlock, cancel_delayed_work_sync, then relock and send OFF. Never cancel synchronously while holding ctx->lock.
- Worker holds ctx->lock for enabled/prepared/stopping check, temporary MIPI_DSI_MODE_LPM flag, DCS 0x0A read and flag restore. Existing K7 mode flags are VIDEO|VIDEO_BURST without LPM. Require direct `mipi_dsi_dcs_read(..., 1)` return exactly 1 and status 0x9D; generic get_power_mode helper does not enforce exact positive byte count.
- Re-arm while holding ctx->lock only if still active; remove must stop/cancel before power-down and DSI detach. Panel lock -> host cmd_mutex is the intended transfer lock order.
- Observation-only; no automatic recovery. Stage 112 design audit only; no source/DTS edits, rebuild or hardware test; MDSS/DSI0/PHY remain disabled.

Stage 113 DSI/DPU and K7 failure/re-enable audit:
- K7 ON/PPS failure is recorded in last_error and powers panel down; void bridge callbacks cannot veto the atomic commit. Refresh-batch failure attempts OFF then powers down. Backlight update failure is logged after enable and does not currently roll back panel enable.
- MSM DSI error IRQ snapshots PLL, FIFO, ACK, timeout, interleave and lane0 PHY errors. Worker software-resets only for MDP FIFO underflow; other conditions are logged and IRQ is re-enabled. This is host-controller recovery, not panel re-init or ESD recovery.
- DPU video flush wait returns -ETIMEDOUT after 50ms; KMS logs and breaks wait loop. Timeout alone is not proof of panel ESD.
- Classification: DCS mismatch vs read/transport failure vs DSI host error vs MDP FIFO underflow vs DPU flush timeout vs K7 init command failure. No generic reset response.
- Future controlled retry only after DRM disable/OFF, normal host/PHY pre-enable, K7 ON/PPS, 90Hz selection and verified first frame. Remain dark on any failure; no blind retry loop.
- Stage 113 is static audit only; no source/DTS change, rebuild or hardware test. MDSS/DSI0/PHY disabled; FPC disabled.

Stage 114 backlight/DSI/DPU frame-completion audit:

- Stage 115 corrected Stage 114 brightness-byte analysis: vendor swaps the value then uses the legacy little-endian helper; Mainline uses the large-brightness big-endian helper directly. Both transmit identical DCS 0x51 payload bytes (0x07ff -> 07 ff). No byte-order source change is required. Actual brightness response remains untested on hardware.

- Stage 114 is static audit only; no source/DTS change, rebuild or hardware test. MDSS/DSI0/PHY disabled; FPC disabled.

Stage 116 Vendor HBM/backlight policy audit:
