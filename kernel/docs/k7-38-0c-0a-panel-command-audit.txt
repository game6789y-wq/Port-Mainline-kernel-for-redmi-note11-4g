Interpretation / transport constraints
- on-command contains 45 packets (570 bytes): first packet is DCS short write 0x11 with 20 ms wait; final display-on packet is DCS short write 0x29; packet 43 has 100 ms wait. All other on packets are DCS long write dtype 0x39, including some two-byte payloads.
- off-command is two DCS short writes: 0x28 with 10 ms wait, then 0x10 with 150 ms wait.
- each 60/90 refresh property is four DCS long-write packets (dtype 0x39) with last flags 0,0,0,1; they are intentionally grouped into one vendor DMA submission.
- Mainline mipi_dsi_dcs_write_buffer() selects short packet for a two-byte buffer, so it cannot preserve vendor dtype 0x39 for two-byte payloads. A raw mipi_dsi_msg with type MIPI_DSI_DCS_LONG_WRITE is needed.
- Mainline MSM DSI host currently creates one DMA packet per transfer and sets the host DMA last-packet bit unconditionally. It has no batch-transfer interface equivalent to vendor mdss_dsi_cmds2buf_tx(). The four refresh commands therefore cannot yet be reproduced with identical batching/last flags through public panel helpers.
